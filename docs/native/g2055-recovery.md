## Disk layout

- Track 0: boot block and the crack loader; the rest of track 0 and track 1 hold filler nothing reads.
- Sectors 22 to 621: the packed program (a short head, 93 packed blocks, the depacker and its stack). The depacker is recovered as code and modelled; its output is the program image, which equals the reference-run memory at the boot settle apart from the bytes the program itself writes after it starts.
- Sector 622: the game's file directory; sectors 623 to 1724: 30 directory entries (two of them containers of the following files), loaded verbatim by the game's own file loader into memory; no code runs from file memory.
- Sectors 1725 to 1759: filler after the last file, never read.

## Copy protection found

- Rob Northen Copylock (the original protection), still present and run by this crack: entered through an F-line trap that the start-up code plants by setting every bit of one instruction byte; an extra XOR layer and trace-vector decoding of its body; it writes two short patches into the game that the game needs (without them two routines start with trap words). The crack bypasses its disk check by restoring one instruction and writing ten bytes into the protection body before it runs. Native port: not ported; the game runs as if it passed.
- A crack-credit check added by the crack: the start-up code stops the game if the intro text no longer contains the crack group's name. Not ported.
- Not protection: a rotate-and-add sum in the depacker whose result is discarded, developer assertion traps in the list code, and the save-disk routines.
- Searched and not found: manual, word, page/line or code-wheel lookups; other track checks; checksum traps over code.

## Cracktro and trainer

- The crack inserts its name as the first lines of the publisher intro text; kept natively as part of the intro.
- No trainer in this variant.

## Reference recordings

A copy of the project's own reference harness (the frozen translated build is untouched) with the game disk attached after the boot snapshot and the disk rotation model the boot needed; 14 recordings (canonical intro run, menus, demo matches, practice, knockout, league, cup, two players, replay goals, a write map and a first-bytes log) give 11737 distinct executed addresses.
